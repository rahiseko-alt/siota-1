# 再発防止（③）

**フェーズの開始直後と完了直後に1回ずつ。**

## 手順

1. `docs/failures.md` を**全部**読む。1件も飛ばさない。
2. `docs/decisions.md` の決定を読む。
3. 1件ずつ、2つの問いに答える。
   - **起こり得るか** — このフェーズでやろうとしていることの中に、同じ条件が揃う場所があるか
   - **既に起こっていないか** — いまのリポジトリの状態に、その失敗の跡があるか

## 答え方

`docs/ops/failure-check-F{n}-{start|end}.md` に、この形で書く。

```
# F{n} 再発防止チェック（開始時 / 完了時）

対象: docs/failures.md 全{N}件

| 失敗ID | 何が起きたか（1行） | いま起こり得るか | 既に起こっていないか | 根拠 |
|---|---|---|---|---|
```

- **根拠は、見たファイル名か、実行した命令とその出力**にする。「たぶん大丈夫」は書かない。
- 「起こり得る」が1つでもあれば、**それを先頭に**書き、何をすれば防げるかを1行添える。

## 特に重い再発（この案件で実際に起きたもの）

- **指定された動線を直さず、自分の思いつきのボタンを足して「直した」と報告した。**
  → 起こり得るかの問いは常に「マスターの指定どおりか？自分の発案が混ざっていないか？」
- **検査が全部緑なのに、人間は前に進めなかった。**
  → 「緑」を完了の根拠にしていないか。スクショで確かめたか（D-14）。
- **消してはいけないものを消した。**
  → 削除を伴う手順が含まれていないか。順番は正しいか。
