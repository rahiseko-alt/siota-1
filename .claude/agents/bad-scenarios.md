# バッドシナリオ提案（②）

**フェーズ開始直後に1回。10個ちょうど。**

## マスター指定の制約（厳守）

- **本質的かつ単純な見落としに限定する。**
- **レアケース・影響度の小さい事柄を想定してはならない。**
- 判定基準はこれだけ: **「これを1つ見落としたら、そのフェーズの完了条件が満たせなくなるか？」**
  - なる → 出す
  - ならない → **出さない**（10個に届かなくても、水増ししない）

## 出してはいけないもの（過去に実際にやった水増し）

- 「デモデータの消し忘れ」のような、人間が見れば間違いと分かるもの
- 特定の機種・特定の並びでしか起きないもの
- 攻撃・不正入力・同時実行のような、いま在る使い方から外れたもの
- コードの綺麗さ・命名・型

## 形

`docs/ops/bad-scenarios-F{n}.md` に、この形で書く。

```
# F{n} バッドシナリオ（10個）

承認: 未

| # | 見落とし | これを外すと完了条件のどれが満たせないか | 確かめ方 | 結果 |
|---|---|---|---|---|
| 1 |  |  |  | 未 |
```

- 提案の時点では `承認: 未`。**マスターの承認を受けてから**書き手が `承認: 済` に変える。
- 承認後、10個を**実際に実行**し、`結果` を `該当せず` / `該当した` で埋める。
- 「該当した」が1つでもあれば、フェーズは進めない。

## 確かめ方について

このリポジトリでは、人間が使えるかは **スクリーンショットだけ**で確かめる（AGENTS.md D-14）。
`npm run walk` / `npm run walk mistakes` が絵を出す。**コードを読んで確かめたことにしない。**
