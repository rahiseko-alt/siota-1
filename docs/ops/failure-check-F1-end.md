## 人が使えるか（D-14・スクリーンショットのみ）

**`npm run walk` は EXIT 1。F1 を閉じても、人間は④で止まったままである。**

まず、はじめに出た赤は**アプリの問題ではなかった**。Playwright が同梱を期待するビルド番号
（`chromium_headless_shell-1217`）と、この環境に在るブラウザ（`chromium-1194`）が食い違い、
起動前に落ちていた。`WALK_CHROMIUM=/path/to/chrome` で実行ファイルを渡せるようにして、
**ブラウザが無いだけの失敗と、アプリの失敗を混同しない**ようにした。

そのうえで出た赤が、本物である。

```
locator.tap: Timeout 30000ms exceeded.
  - locator resolved to <button onclick="App.goToStep(4)" class="boxbutton boxbutton--white">…
  - <div>左耳 (L)</div> from <div class="editor-wrapper">…</div> subtree intercepts pointer events
    at tapText (/home/user/siota-1/scripts/walk-human.mjs:69:16)
```

- 撮れたのは **4コマ**（`①URLを開いた` / `②ログインした` / `③犬の名前を選んだ` / `④カルテを書いた`）
- **⑤へ進めない。**「確定してお客様カルテ」を押そうとすると、`左耳 (L)` の要素がタップを奪う
- 原因は `docs/ops/plan.md` 第3章の **463px 問題**（④の編集領域が横 463px 必要・iPhone 13 は 390px）
- **直し方はマスター判断**（(a) 編集領域だけ横スクロール容認 / (b) モックのレイアウト意図に沿った縮小）。
  私が新しいデザインを発案しない

**F1 の完了条件に画面の到達性は含まれない**（A・B・C は隔離と機械検査だけ）。
だから F1 は閉じられる。**閉じられることと、人が使えることは別である。**
④→⑤は **F2** の作業で、そこが plan の中心にある。
