## 絵が見つけたもの

### ① 確定後に「03 カルテ作成」へ戻ると、見出しが「**ポンチ** カルテ入力」 → **直した**

`X` で確定したあと1タッチで戻ると、見出しが**仮データの犬の名前**になる
（`mistakes/08`）。同じ画面は、犬を選び直したときには正しく「X カルテ入力」と
出ている（`mistakes/03`）ので、**確定を経由したときだけ**起きている。

**なぜ問2の ✕ か**: 戻ること自体は1タッチでできる。しかし人は
「いまどの子のカルテを開いているか」を見出しで確かめる。そこに**預かっていない犬の
名前**が出ているので、**直したかった操作（`X` のカルテを直す）を安心して続けられない**。
書き始めてよいのかどうかが、絵からは判断できない。

**判定の時点では、どのレベルの問題かを断定しなかった**（D-14 はコードを読まないため）。
判定を出したあとに調べた結果は次のとおり:

- 確定すると保存したカルテの URL へ**開き直す**ため、この経路は `selectKarte()` を通らない。
  そのため見出しが HTML の初期値のまま残っていた
- **書き込み先の事故ではない。** `commitReport` は URL の `__REPORT_CONTEXT__.petId` を
  使うので、そこで書いても正しい子に入る
- とはいえ**人は見出しでどの子かを確かめる**ので、絵の判定として ✕ は正しい

`showReport()` で見出しをその犬に合わせ、HTML の初期値からは意匠モックの犬の名前を
外した（選ぶ前は空。分からないものを分かっているように見せない・`D-10`）。
