## 3. コードや緑/赤しか見ていない箇所は、正しく動くか

### A-5【直した】確定カルテが0枚の犬で、今日量った体重が捨てられる

`backend/js/magazine-view.js` はこう書いていた:

```js

**`[]` は真**なので `data.weights` へ落ちてこない。実測（⑤で下書きを開いたときの実レスポンス）:

```

## 4. 脆弱性

**越境は起きていない。実測で確認済み。** 唯一の防波堤は RLS で、
呼び出し元（`worker/src/index.js`）にペット所有チェックは無いが、RLS は全部止めた。

| # | 攻撃 | 結果 |
|---|---|---|
| 1a | 飼い主Aのトークンで、飼い主Bの犬に同一 REST URL | `200 []` |
| 1c | 招待未消化の人が、他人の犬に同じ URL | `200 []` |
| 2a | `GET /api/my/pets/{他人の犬}/reports/{他人のカルテ}` | `404` |
| 2c | 自分の犬 × 他人のカルテID | `404` |
| 2d | 飼い主がスタッフ経路へ | `404` |
| 2g | トークン無し | `401` |
| 7a/7b | 店1のスタッフ／管理者が店2の犬へ | `200 []` |
| 7c | 店1スタッフ → 店2の犬のカルテ（worker 経由） | `404` |
| 9a | 飼い主がスタッフ経路で自分の犬の**下書き**を要求 | `404`（`status='final'` 必須） |
| 10 | 退会扱い（`owners.active=false`）にしてから再試行 | `[]` / `404` |

効いている本質: **Worker は `service_role` キーを一切持たない**——常に呼び出し元の
アクセストークンを Bearer に載せるので、RLS が最後に必ず効く。

- **注入**: `petId` は `isUuid()`（`url.pathname` は percent-decode されないので `%2c` も弾く）＋
  `encodeURIComponent` ＋ RLS の三重。`or=(pet_id.eq.X,pet_id.eq.Q)` を素の PostgREST に
  投げても、返るのは自分の犬の分だけ
- **XSS**: `npm run verify:xss` **24/24 PASS**（`weights[].ym` の3項目を含む）。
  `renderWeightDiff()` は `textContent`、`renderWeightGraph()` は `createElementNS` +
  `setAttribute` + `textContent` のみ。`innerHTML` は固定テンプレートだけ
- **出口**: `weightHistoryFromReports()` が `{ym, date, kg}` を**組み直して**返すので、
  他カルテの `data`（スタッフメモ・`__marks`・写真参照）は1バイトも出口に出ない（実測）

### 直していない・記録する

- **増幅（中）**: ④を開くたび HTTP 往復が2本増え、その本文取得が worker 側で
  `listWeightHistory`（**全確定カルテの `data` 全文**を select）を毎回走らせる。
  確定カルテ40枚×約1MBの犬でカルテ1枚を GET したとき、クライアントに返るのは 979KB なのに
  **Worker は 38MB を上流から読んで捨てている**（実測: staff 5,751ms / owner 14,117ms）。
  GET は `enforceRateLimit` の対象外（10箇所すべて書き込み系・grep 実測）。
  実データの `data` は `asset://` 参照なので現実の犬で 40MB には届かない見込みだが、
  **増幅の構造自体は入った。** → `#47`
- **認可の非対称（低）**: スタッフ経路は `Promise.all` なので、`getReport` が 404 でも
  体重クエリは既に飛んでいる。RLS で `[]` なので漏れないが、飼い主経路の
  「所有確認の後に読む」順序とは非対称

## 5. マスターの判断が要ること

### ① 古いカルテを開いても、そのあとの回の体重が線に乗る

`listWeightHistory(petId)` は開いているカルテの日付で切っていない。
飼い主が5月のカルテを開くと、上の「体重」欄は 4.2kg なのに、下のグラフは「直近: 2026-09 4.6kg」。
**「推移」としては自然だが、1枚のカルテの中に未来の値が混ざる。** 意図どおりか。

### ② `?revise=1` で**古い**確定カルテを直すと、犬体図が消える（既存・今回の変更ではない）

`revise_report` は `data` の**全置換**。`__marks` を持たない（＝ `70c264d` より前に確定した）
カルテを直すと、印を戻せず `bodyMarkingImage` が**キーごと消える**——
**飼い主に届いていた犬体図が、直した瞬間に消える。**
`70c264d` 以降に確定したカルテでは起きない。**本番に既存カルテが在るなら、納品前に知らせるべき。**

### ③ 体重欄に `min` が無い（低）

`-1` と打つと3箇所で解釈が食い違う（前回比は「量っていない」扱い／未記入判定は「記入済み」／
`extractReport` は `-1kg` を保存して⑥に届く／履歴からだけ消える）。`min="0.01"` 1つで揃う。
既存の穴だが、今回の `kg <= 0` 落としで食い違いが1つ増えた。

## 6. イレギュラーな操作をして壊れないか

人がやりがちな「変な操作」を、実機と同じ形で通した。

| 操作 | 結果 |
|---|---|
| 引き継ぎの往復が終わる前に打ち始める（応答を4秒遅らせて**必ず**レースを作った） | 打った文字は消えず、引き継ぎの帯も出さず、前回の爪・BCS も入らない |
| コース未選択のまま確定 | 関所が止め、④に留まる（空の器へ運ばない） |
| 確定前に段のタブ「04」 | 移りはするが「まだ確定していません」の一言に差し替わる（**意図した設計**。雑誌の残骸 0）。「03」へ戻れる |
| 体重に `-5` / `0` / `999999` / `4.4001` | どれも壊れない。空にすると前回の値に戻る |
| 「白紙にする」の連打 | 例外なし |
| 存在しないカルテ番号を URL で開く | 白い画面にならない（文字数 10,974） |
| **壊れた `petId`（`not-a-uuid`）を URL で開く** | **`404` で本文が空**。ブラウザ自身のエラー画面になる → `#48` |

`+999994600g ▲` のような桁は出るが、`type=number` に人が打てる範囲での話で、壊れてはいない。
**過剰に直さない**（マスター指示の独立検証④）。

浮動小数点は問題なし: `Math.round((now - prev) * 1000)` を総当たりで検算し、
**80万組で不一致 0**（2桁±0.5kg / 2桁任意差 / 3桁±0.2kg）。`Number.EPSILON` 対策は不要。

## 7. 致命的な見落とし

### A-3【最重要・直した】下書きを再開すると、前回の所見が黙って今回の所見になる

**1回目は帯が出るが、2回目以降は帯だけが消え、値だけが残る。** 実測:

```
【1回目に開いたとき】
 band: true / "2026-05-01 のカルテから 爪・耳・歯・BCS・ベスト体重・犬体図の印 を引き継ぎました。…"
 nailActive 2 / earActive 2 / teeth "歯石が厚い😥" / bcs 1 / bestWeight "4.2"
 dock: "未記入: コース・体重・担当からのメッセージ"

（画面のどこかを1回触る → 下書きが1枚できる）

【2回目に開いたとき】
 band: false / bandText: ""                    ← 告知が消えた
 nailActive 2 / earActive 2 / teeth "歯石が厚い😥" / bcs 1 / bestWeight "4.2"  ← 値は前回のまま
 dock: "未記入: コース・体重"                    ← 残り2つを埋めれば「全項目入力完了 (8/8)」
```

下書き分岐は `applyCarryOver()` を通らないので、帯を出す唯一の場所に届かない。
`watchDraft()` は `pointerdown` でも走るので、**画面を1回タップしただけで**この状態になる。
確定の直前にも警告は無い（`commitReport()` が確かめるのはコースだけ）。
完了バッジは「入っているか」しか見ないので、引き継いだ5項目を**今回入力したものと同じに数える。**

トリマーが「爪 Lv.2」を見て触らなければ、それは**前回の所見のまま「今回の所見」として
飼い主に届く。** `6fecedc` で消した「読み込みました と言いながら何もしていない」の**裏返し**
——何かしているのに何も言わない（`D-12`）。

**直し方**: 持ち回りの印は増やさない。**手元の前回のカルテと突き合わせて、いま同じものだけを言う**
（`carryOverStillSame()`）。こうすると「引き継いだから同じ」でも「たまたま同じ値を入れた」でも、
言っていることは正しい。

`clearCarryOver()`（白紙にする）は**出さない**——ここまでに今回の体重やコースが入っている
ことがあり、初期値に戻すと**人が入れたものを消してしまう**。項目はすぐ上に並んでいるので、
直すのは1つずつでよい。

**実測（直したあと・`14/14 PASS`）**:

```
PASS  1回目: 引き継ぎの帯が出る
PASS  1回目: 「白紙にする」が押せる
PASS  2回目: 前回のままの項目を、黙らずに名指しで言う
      "爪・耳・歯・BCS・ベスト体重・犬体図の印 は 2026-07-01 のカルテのままです。
       今回見た結果に直してから確定してください。"
PASS  2回目: 「白紙にする」は出さない（人が入れた分まで消さない）
PASS  2回目: 打った文字は残っている
```

途中、**キーの並び順で比べていたせいで耳と爪だけ名指しから漏れた**（`{right,left}` と
`{left,right}` が `JSON.stringify` では別物）。保存の形は `extractReport()` が決めるので、
並び順は約束のうちに入っていない。**値そのものを1つずつ見る**形に直した。

### A-7【直した】実装と食い違うコメント（`AGENTS.md` A-5）

`saveDraft()` のコメントが「⑥ は読まないキーなので、**確定のときに落とす**」と書いていたが、
`70c264d` 以降 `commitReport()` は `__marks` を**落とさず載せる**。
このリポジトリではコメントが次の人の判断を決めるので、直した。

### 指摘なしと結論した項目（理由つき）

- **`__marks` が⑥飼い主の画面に描かれる経路は無い**: `magazine-view.js` に
  `Object.keys` / `Object.entries` / 汎用ループが1件も無い（grep 実測）。`data.*` はすべて名指し
- **下書きが2枚生える経路は無い**: `watchDraft()` は往復が終わってからしか呼ばれず、
  `saveDraft()` は `draftSaving` で二重起動を止める
- **別の犬の下書きに書き込む経路は無い**: 犬の切り替えは `location.href` で**全ページ遷移**する。
  ただし SPA 化したら即座に事故になる（`resumeDraft` は下書きが無いとき `draftReportId` を
  null に戻さない）
- **W-4（打鍵中の書き戻し）の保護は生きている**: 2通りに壊して両方赤を確認
- **写真・印が落ちる経路は新設されていない**: `applyReport()` も `extractReport()` も未変更
