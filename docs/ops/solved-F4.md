### 9. 実顧客を入れる前に、バックアップの発火条件を素通りする
種別: 解決

**原因**: `D-20260827-46`（バックアップは実顧客データが入るまで用意しない）の
**発火条件は「本番に実顧客のカルテを1件でも入れる前」**で、それが発火するのは F4 の中。
ところが条件は `docs/deferred.md` #35 の1行にしか無く、**納品の手順書
（`docs/runbook.md`）にはチェック項目として存在しなかった**。手順書に無いものは、
納品する人が思い出さないかぎり実行されない（`plan.md` 7-1 の「人が思い出して叩く検査は
納品後には走らない」と同じ形）。

**直したこと**: `docs/runbook.md` に **`## 2-D. 実顧客のカルテを本番へ入れる前に見ること`**
を新設し、5項目を表にした（バックアップ／同姓同名／ダミー掃除／鍵ローテ／本番の版）。
発火条件が1か所（`deferred` の行）ではなく、**納品の道の上**に載った。

**判定は「節が在る」ではなく「5項目が在る」で採る。** 見出しだけ足して中身が空でも
「在る」になってしまうため、行を数える（`^| [1-5] | **` の5行）。

#### 直す前（赤）
`f2f1fdd^`（2-D を足す前）の `docs/runbook.md` に、同じ判定を掛けた。

```
$ git show f2f1fdd^:docs/runbook.md > /tmp/runbook-before.md
$ node /tmp/check9.mjs /tmp/runbook-before.md
NG  実顧客を入れる前に見ることが手順書に無い（節=無 項目=0）
```

#### 直した後（緑）

```
$ node /tmp/check9.mjs docs/runbook.md
OK  実顧客を入れる前に見ることが手順書に在る（節=有 項目=5）
```

#### 直しを戻した（また赤）
いまの `docs/runbook.md` から `## 2-D.` の節だけを落とした複製に、同じ判定を掛けた。

```
$ node /tmp/check9.mjs /tmp/runbook-reverted.md
NG  実顧客を入れる前に見ることが手順書に無い（節=無 項目=0）
```

判定に使った述語（`/tmp/check9.mjs`）:

```js
const t = fs.readFileSync(process.argv[2], 'utf8');
const sec = /^## 2-D\./m.test(t);
const rows = (t.match(/^\| [1-5] \| \*\*/gm) || []).length;
console.log(sec && rows >= 5 ? 'OK  …（節=有 項目=' + rows + '）' : 'NG  …');
```

### 1. 棚卸しの判断が、古い記録を根拠にしている
種別: 解決

**原因**: 記録は**書いた日の理解で固まる**。直した人が元の行に戻って来ないので、
「まだ在る」と書いてある項目が実は直っている（36件中7件）。逆向きはもっと危なく、
`#26` は「選び直しになるだけ」と書いてあったが**飼い主に届いた中身が消える**欠陥だった。
**同じことは記録の中だけでなく、コードの説明文でも起きる。**

**直したこと（2026-08-27）**: `worker/src/index.js` のコメント7か所が、もう存在しない
注入（`__SCREEN__` 等）と削除済みのテンプレート名（`ponchi-v2.html`）を説明したままだった
のを書き直した。

**そのうえで 2026-08-28、この項の確かめ方（「行が名指しするファイルを実際に開く」）を
記録の側にも掛けたところ、`docs/failures.md` に無い `F-20260827-44` を
コードが2か所から参照していた**（`src/index.html:652` / `scripts/verify-photo-roundtrip.mjs:4`）。
番号を採ったが本文を書かなかったもので、**`grep` した次の人には何も出ない**。
本文を書いて埋めた。

判定は「コードが指している番号に、記録の本文が在るか」で採る。

#### 直す前（赤）

#### 直した後（緑）

#### 直しを戻した（また赤）

### 5. この環境で走らない検査を、「通った」と書く
種別: 回避

先送りの記録: `docs/deferred.md` #37（Docker はこの環境にもマスターの Windows にも入れられない）

**原因**: この環境に Docker が無く、`verify:*` **15本**と `verify:migrations` は
**手元で1本も走らない**。にもかかわらず「検査は通っています」と書けてしまう。

**直していない（直せない）**: Docker はこの環境に入れられず、マスターの Windows にも
入れない。**代わりに CI が持っている**——GitHub のランナーで `supabase start` が動き、
`verify` job が15本を走らせる（2026-08-27 の master で全緑）。

**運用に落としたこと**: 緑を主張するときは **その緑を出した場所（手元か CI か）を必ず書く**。
この記録の中でも、`empty-pass` は「手元で緑」、`verify:admin` は「CI 判定待ち」と分けて書いた。

**なぜ「解決」と呼ばないか**: 原因（手元で走らない）は消えていない。人が書き分けるだけなので、
忘れれば同じことが起きる。`種別: 回避` が正しい（`D-18` 偽-3）。

### 3. `.gitignore` に鍵を足して、**もう安全だ**と思い込む
種別: 解決

**原因**: `.gitignore` は**すでにツリーに入っているファイルには効かない**。
「足したから安全」は、足す前の状態によっては嘘になる。確認は 2026-08-26 のもので、
その後の変化を見ていなかった。

**直したこと**: 鍵3種（`.cftoken` `.sbtoken` `.srkey`）を `.gitignore` に足し、
**2つの命令で確かめた**——`git check-ignore -v` が3本とも無視すること（3/3）と、
`git log --all` が3本とも 0 件のままであること。
`no-secrets` が緑であることは根拠にしていない（あれは**形で捕まる種類だけ**を見る）。

判定は「行が在る」ではなく「**git が実際に無視している**」で採る。

#### 直す前（赤）
`f2f1fdd^`（3行を足す前）を作業場に取り出して掛けた。

```
$ git worktree add --detach /tmp/before f2f1fdd^
$ bash /tmp/check3.sh /tmp/before
NG  鍵3種が無視されていない（0/3）　履歴 0件
```

#### 直した後（緑）

```
$ bash /tmp/check3.sh .
OK  鍵3種は無視され（3/3）、履歴にも 0 件
```

#### 直しを戻した（また赤）
いまの `.gitignore` から3行だけを落として掛けた。

```
$ grep -vE '^\.(cftoken|sbtoken|srkey)$' .gitignore > /tmp/gi.new && cp /tmp/gi.new .gitignore
$ bash /tmp/check3.sh .
NG  鍵3種が無視されていない（0/3）　履歴 0件
```

判定に使った述語（`/tmp/check3.sh`）: `git check-ignore -v` の行数が3、かつ
`git log --all --oneline` の行数が0のときだけ OK。**片方だけでは足りない**——
無視されていても既に履歴に入っていれば手遅れであり、履歴が0でも無視されていなければ
次のコミットで入る。

### 2. 未参照ファイルを消したら、消してはいけないものだった
種別: 保留

**先送りの記録**: `docs/deferred.md` #5（アイコン5点・`body-side.png`）／ #6（`konva.min.js`）

**確かめた結果（2026-08-27）**: 未参照ファイル7点について、参照する側ではなく
**記録・ルールが名指ししている側**を数えた——`konva.min.js` **9件**
（`AGENTS.md` の確定スタック表を含む）／ `body-side.png` 5件／ `icon-*.png` 各3〜4件。
**どれも「置いてあるだけ」ではなく、記録が指している。**

**直していない**: この項が求めているのは「消す前に2方向から数える」であって、
**消すこと自体ではない**。数えた結果は「消してはいけない」だったので、
F4 では**1つも消していない**。

**なぜ「解決」と呼ばないか**: 原因（未参照＝不要と読む癖）は消えていない。
消してよいかは「`AGENTS.md` の確定スタック表から `konva.min.js` を外すか」という
**マスターの判断**とセットで、それは出ていない。判断が出るまで保留（`D-18` 偽-3）。
