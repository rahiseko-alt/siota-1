### 4-0. 土台 — 検査が走る場所を作る（**いまここ**）

> **なぜ結線より先か**: F3 の完了条件は「実データで D-14 の2問」。
> それを見る検査（`verify:*`）が **9本とも消えている**（`#6`）。
> **繋いでから「検査が動かない」と気づくのが一番高くつく**——`#8`（`walk` が新しいコンテナで
> 動かなかった）で実際に起きた。だから土台を先に固める。

**根っこの問題**（マスターの問いから特定した）:
**一番大事な検査が「特定の一台の机の上でしか動かない形」で作られている。** 症状は3つ、原因は1つ。

| 症状 | 実測 |
|---|---|
| 接続先がハードコード | `scripts/lib/local-stack.mjs` は `127.0.0.1:54321` 固定・`process.env` 参照 **0件** |
| 自動で走る検査がゼロ | `.github/workflows` が**存在しない**。人が叩かない限り何も走らない |
| 記録を手で書ける | `supabase/.sql-verified` はただのテキスト（`#5` の代用品） |

**やること（この順）**:

| # | やること | 完了の見え方 |
|---|---|---|
| 0-a | `local-stack.mjs` の接続先を `SUPABASE_LOCAL_URL` で差し替え可能にする | ✅ **完了**。直書きに戻すと検査が落ちる |
| 0-b | **CI の骨組みを置き、実際に走ることを確かめる** | ✅ **完了**。`33件の変更（origin/master から）`＝素通りしていない |
| 0-c | CI に `supabase start` を足す（**ランナー側に Docker が在る**） | ✅ **完了**。`4/4 PASS`・`pets を実際に引ける HTTP 200 / 1件` |
| 0-d | **`verify:*` を作り直す**（`#6` の本体） | 🔄 **1/9**。`verify:portal` が CI で **14/14 PASS**。残り8本は 4-1 とセット |

**0-c で自分の検査の欠陥を1つ見つけた**（`F-20260825-35`）。初回は `4/4 PASS` だったが、
`PASS  マイグレーションが当たっている（pets が引ける）  HTTP 401` という行が出ていた。
**401 はテーブルの有無と無関係**で、合格条件を `status !== 404` にしていたため
**マイグレーションが1本も当たっていなくても PASS** していた。
再発防止は「**合格条件を『〜でなければ合格』で書かない。期待する成功の形
（ステータス・中身の型・件数）を直接書く**」。9本を戻すときに直接効く。

**0-d の1本目が証明したこと**（CI で `14/14 PASS`）:
`#7` の器の復元が**実ログイン・実データ・RLS 下でも成立**すること／
`#10` の橋が**実 Worker 経由でも載る**こと／そして**私が走らせられない検査が走る**こと。
最後の1つがこの工事の目的そのもの。

**CI で `supabase start` を使うと、鍵を1本も CI に置かずに済む**（`A-1` と相性が良い）。
これは実在の Supabase プロジェクトを検査に使う案より安全なので、そちらを採らない。

**9本のうち、いま戻せるのは1本だけ**（実測で切り分けた）:

**`/edit` を正UI へ向け直すのは結線そのもの**なので 4-1 で扱う。
