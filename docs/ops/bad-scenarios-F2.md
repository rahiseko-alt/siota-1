### 11. 検査が「カルテを書いた」と言いながら、実際には何も書いていない — 結果: 該当した（実測中に発見）

- **人間**: 写真には「カルテを書いた」と出ているのに、**画面には何も書かれていない**。書かないまま「最後まで行けた」と判定してしまう。
- **AI**: `walk-human.mjs:56-59` が `[contenteditable="true"]` を探すが、**現 UI に `contenteditable` は 0件**（`grep -c contenteditable src/index.html` → 0）。`scrollIntoViewIfNeeded()` と `tap()` の失敗は `.catch(() => {})` で握りつぶされ、`keyboard.type()` はフォーカスの無いまま流れる。確かめ方: `npm run walk mistakes` の `04-M2_0_記入中.png` と `06-M2_2_...png` を並べる → **同一**。書きかけが「消えた」のではなく**最初から入っていない**

**なぜこれが完了条件を崩すか**: D-14 の2問はどちらも「**やりたかった操作を完了できたか**」を見る。
入力が一度も入らないなら、①〜⑥を通っても**「書いて、届いた」ことは何も証明していない**。
`F-20260821-11`（受入基準を満たすことと機能が動くことの取り違え）と同じ形が、検査の側で起きている。

**あわせて見えたこと**: ⑦担当トリマーからのメッセージには**既定文が最初から入っている**ため、
何も書かなくても文章で埋まって見える。**「書いていない」ことが画面から分からない**
（`F-20260821-14` と同型）。水増しを避けて落とした候補に入れていたが、**#11 と組み合わさると完了条件に効く**ので格上げする。
